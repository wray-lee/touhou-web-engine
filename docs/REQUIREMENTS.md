**一句话结论**：外壳与内核主干都在浏览器里跑出零售素材，本轮把「六个面」真正拼成了「一个游戏」：同一次 `TH08Game` 实例里用只读画面的鼠标手从零致死跑完 `stage1 → 2 → 3 → 4b → 5 → 6a → 6b`（零死亡零续关，结算 `campaignFinished`），并且允许真死真续关再跑一遍，验证每次续关都回到结束的那一面。同时修掉一个真实缺陷——关卡结算只清弹不清激光，面末未走完的光束会以冻结几何画满 180 帧通关横幅。
**剩下的缺口**：`stage5` 需要击杀才继续的最后一段（不开火时时间线在 `case 10` 等 Boss 死，是零售语义而非缺陷）；零售标题屏 / 结算屏美术（`title01.anm` / `result00.anm` 已解包，但脚本→精灵分配缺 `TitleScreen` 实现，无从引用）；`eff01..eff09*` 特效包未接（模板表 `g_EffectTemplates[66]` 在 exe 的 `.data@0x4c6d30`，本轮全盘复查确认 **磁盘上没有 th08.exe**，`scriptIdx` 又是「本关 eff 包内」的局部号，详见 R-12 §4）；浏览器侧一坐到底录像；以及 R-9 / R-10 / R-11 列出的开放条目。

## R-15 本轮（2026-09-15 续）：音轨的循环点与整条音效总线

这一轮全部围绕「听」。前面几轮把画面、流程、数值推到实测级之后，声音仍然是最薄的一层：BGM 每两分钟重播一次前奏，音效表是一份猜出来的名字，而且所有音效一样响。

### 1. BGM 缺的不是文件，是循环点

`thbgm.fmt` 每首歌给两个长度：前奏（intro）与主体（loop），磁盘上那条 ogg 是两者**首尾相接**的一整条。零售的回卷点落在主体开头，而 `HTMLAudioElement.loop` 只会回到 0，所以此前每首歌每隔 `totalSeconds` 就把前奏重播一次——整份音轨里最响的「这不是原作」。

改法：`BgmOptions.loopFromSeconds` + `startLoopWatch()`（25 ms 轮询播放头，接近末尾回卷到 `introSeconds`；另挂 `ended` 兜底，防标签页被节流后直接跳过窗口）。三条硬约束：给出循环点时才关掉元素自带的 loop；暂停时不回卷，否则 resume 会把前奏带回来；`stopBGM()` 必须撤掉轮询。

### 2. 顺手抓到的两个音量真 bug

- **换歌覆盖用户音量**：两处调用点硬编码 `volume: 0.7`，而 `applyPrefs()` 在 boot 就把音量滑块的值交给 `setBgmVolume()`——于是每换一关，用户的音量设置被按回 0.7。现在调用点不传 `volume`，交回全局音量。
- **标题屏 BGM 开关**：`toggleBgm()` 恢复时调 `playBGM(undefined, ...)`，会把正在放的关卡主题曲换成内置合成琶音。改成 `pauseBGM()` / `resumeBGM()` 对调。

### 4. 引擎侧的音效总线

零售的音效不是「立刻响」，而是**按帧排队**：`PlaySoundByIdx` 写进 `soundQueue[12]`（`SFX_QUEUE_LENGTH`，`SoundPlayer.hpp:85`），同一帧里重复索引只留一份、声像取平均，帧末一次放出，且每个索引只有一个声部（`Stop()` + `SetCurrentPosition(0)` + `Play()`）。音量滑块走 `1-(1-f)^3` 的三次锥度，并在 mB 域平移整条总线（`SoundPlayer.cpp:830-839`）。

这三条都可听：少了按帧合并，一屏几百发弹就是几百声枪响；少了 mB 电平，本该 -19 dB 的细碎音会盖过一切。

新代码全在引擎里，而且**不认识 th08**：

- `src/engine/audio/SeBus.ts`：队律 + 声律 + 单声部 + 逐索引增益，`SeBusSource{files,entries,names}` 由游戏注入。
- `src/engine/audio/Wav.ts`：自带 RIFF 读者。素材是 22050 Hz / 单声道 / **8-bit 无符号** PCM，`decodeAudioData` 对各浏览器 8-bit 的支持不一致，自己读字节反而确定；顺带处理奇数长度 chunk 的对齐填充。
- `AudioManager`：删掉 `TH08_SE_MAP` 与 `playTH08SE`（那是共享层最后一处「引擎知道某个游戏的文件名」），`playSE(name)` 经注入的 `names` 落到索引，拿不到音表时仍回退合成 blip，所以无素材环境与全部测试一样有声。
- 首帧缺录音的请求最多再等 20 帧（`SE_RETRY_FRAMES`），因为端口是流式取素材而非开机全量驻留；等不到就永久标记缺失，不会吊着队列。

sim 侧原来 `EnemySlot.playSfx` 只留 id、丢了 x，而零售走的是 `PlaySoundPositionedByIdx(idx, x)`。现在 `frameSfx: SeTick[]`（`{id,x}`），宿主按 `((x-192)/192)` 换算声像——就是零售那句 `((pan - 192) * 1000) / 192` 的 -1..1 版本。另外 `playSfx` 的门槛从 `id > 0` 改回零售的 `id >= 0`（`NO_SOUND` 是 -1），否则索引 0 永远点不响。

- **把 `L132` 从「有度量、没画」推到「按零售语义画出来」。** 硬件雾是片元上的颜色混合，这件事没有 shader 做不到：上一轮证伪的纯色底片会往透明洞里刷雾，而「同一张几何再描一遍、tint 设成雾色」也不行——tint 是**乘**在纹素上的，雾色会被它本该替换的那个场景颜色染暗。剩下的唯一正确入口就是片元本身，所以 `src/engine/renderer/FogShader.ts` 把雾写成 Pixi v8 的高阶 shader bit，WGSL 与 GLSL 各一份，围绕 Pixi 自己的 mesh 模板装配（采样、局部变换、roundPixels 仍然用它的位），雾排在最后：bit 是按列表顺序写同一个 `outColor` 的。
